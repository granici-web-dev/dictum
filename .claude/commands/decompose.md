Прочитай `outputs/prd.md`. Работай с таблицей «Скоп MVP»: строки с `ID`, приоритетом, зависимостями и критерием готовности.

## Алгоритм

1. Возьми только строки Must и Should. Could и Won't — в отдельный список «Отложено», без разбивки.
2. Сгруппируй строки в **фазы** по зависимостям: фаза N содержит только то, чьи зависимости закрыты фазами < N. Первая фаза — всегда «сквозной сценарий»: минимум, при котором главный сценарий из PRD проходит от начала до конца.
3. Каждую строку разбей на **issues**. Правила размера и формы:
   - один issue — не больше одного рабочего дня для одного человека; если больше — режь дальше;
   - у каждого issue есть `title` (глагол + объект, ≤ 60 символов), `description` (2-4 предложения: что и зачем), `dod` (Definition of Done — 2-3 проверяемых пункта), `depends_on` (ID других issues), `phase`, `scope_id` (ID строки PRD), `area` (frontend / backend / design / infra / research);
   - не создавай issues вида «сделать бэкенд» или «настроить проект» без конкретного результата;
   - не создавай issues на то, чего нет в PRD — если чего-то не хватает для реализации, добавь в «Открытые вопросы», а не в бэклог.
4. Проверь граф зависимостей: без циклов, каждый `depends_on` существует.
5. Сохрани два файла.

## Выход

`outputs/issues.json`:

```
{
  "source": "outputs/prd.md",
  "lang": "[из brief.md]",
  "phases": [
    { "n": 1, "title": "Сквозной сценарий", "goal": "…" }
  ],
  "issues": [
    {
      "id": "I-001",
      "phase": 1,
      "scope_id": "S1",
      "area": "backend",
      "title": "…",
      "description": "…",
      "dod": ["…", "…"],
      "depends_on": []
    }
  ],
  "deferred": [ { "scope_id": "S7", "reason": "Could" } ],
  "open_questions": ["…"]
}
```

`outputs/issues.md` — то же самое для чтения человеком: по фазам, внутри фазы — список issues с DoD. Этот файл показывается на воротах перед публикацией: пользователь правит его, и только после подтверждения `/publish` берёт `issues.json`.

## Правила

- Язык — из frontmatter брифа.
- Не выдумывай требования. Сомневаешься — в «Открытые вопросы».
- Идентификаторы стабильны при повторном прогоне: если PRD не менялся, `I-001` остаётся `I-001`.
