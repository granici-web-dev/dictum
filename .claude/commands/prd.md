Прочитай:

- `outputs/brief.md` — обогащённый бриф (результат `/brief`); язык бери из его frontmatter
- `outputs/research.md` — синтез ресёрча (результат `/research`)
- `templates/prd_oneshot.md` — фиксированный шаблон одностраничного PRD

Заполни шаблон по структуре, опираясь на бриф и ресёрч.

## Маппинг секций

- **Что это** — суть продукта из брифа (категория «Функциональность» + «Пользователи»).
- **Целевая аудитория** — из категории «Пользователи» брифа.
- **Главная проблема** — основная боль ЦА, проходит через бриф и подтверждается в ресёрче.
- **Ключевые сценарии использования** — 3-5 сценариев из «Функциональности».
- **Конкурентный ландшафт** — 3-5 продуктов из секции «Что делают конкуренты хорошо» ресёрча, плюс предложение «вот пробел, который мы закрываем» (из секции «Чего им не хватает»).
- **Скоп MVP** — таблица с MoSCoW по сценариям и экранам. Расставь приоритеты сам, обоснованно: что Must для главного сценария, что Should для вспомогательных, что Could/Won't для отсечения.
- **Метрики успеха MVP** — из категории «Бизнес-цели» брифа, в числовом виде.

## Требования к таблице «Скоп MVP»

Эта таблица — вход для `/decompose`, поэтому у каждой строки обязательно:

- `ID` вида `S1`, `S2`, … — стабильный, на него будут ссылаться issues;
- `Приоритет` — Must / Should / Could / Won't;
- `Зависит от` — ID других строк или `—`;
- `Критерий готовности` — одно проверяемое предложение: как понять, что строка сделана.

## Правила

- Не выдумывай факты, которых нет в брифе или ресёрче.
- Если данных не хватает — оставь явный placeholder вида `[уточнить: что именно]`.
- В конце вывода добавь раздел `## Открытые вопросы` со списком всего, что нужно уточнить у пользователя или продакта.

Сохрани финальный PRD в `outputs/prd.md`.
