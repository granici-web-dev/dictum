Прочитай:

- `outputs/brief.md` — обогащённый бриф (результат `/brief`); язык бери из его frontmatter
- `outputs/research.md` — синтез ресёрча (результат `/research`)
- `templates/prd_oneshot.md` — фиксированный шаблон одностраничного PRD

Заполни шаблон по структуре, опираясь на бриф и ресёрч.

## Маппинг секций

- **What it is** — суть продукта из брифа (категория «Функциональность» + «Пользователи»).
- **Target audience** — из категории «Пользователи» брифа.
- **Core problem** — основная боль ЦА, проходит через бриф и подтверждается в ресёрче.
- **Key use cases** — 3-5 сценариев из «Функциональности».
- **Competitive landscape** — 3-5 продуктов из секции «Что делают конкуренты хорошо» ресёрча, плюс предложение «вот пробел, который мы закрываем» (из секции «Чего им не хватает»).
- **MVP scope** — таблица с MoSCoW по сценариям и экранам. Расставь приоритеты сам, обоснованно: что Must для главного сценария, что Should для вспомогательных, что Could/Won't для отсечения.
- **MVP success metrics** — из категории «Бизнес-цели» брифа, в числовом виде.

## Требования к таблице «MVP scope»

Эта таблица — вход для `/decompose`, поэтому у каждой строки обязательно:

- `ID` вида `S1`, `S2`, … — стабильный, на него будут ссылаться issues;
- `Priority` — Must / Should / Could / Won't;
- `Depends on` — ID других строк или `—`;
- `Done when` — одно проверяемое предложение: как понять, что строка сделана.

## Правила

- Не выдумывай факты, которых нет в брифе или ресёрче.
- Если данных не хватает — оставь явный placeholder вида `[уточнить: что именно]`.
- В конце вывода добавь раздел `## Open questions` со списком всего, что нужно уточнить у пользователя или продакта.
- Заголовки секций и названия колонок бери из шаблона слово в слово: они английские при любом `lang` (`CLAUDE.md` §4). На языке прогона — содержимое.

Сохрани финальный PRD в `outputs/prd.md`.
