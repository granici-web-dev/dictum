## Фаза 1 — Сквозной сценарий

Цель: Бот ежедневно в 9:00 получает из Trello карточки с дедлайном сегодня или просроченные, с указанием ответственного по каждой, и отправляет сводку в командный чат.

### I-001 · Настроить доступ к Trello API
- **Скоп:** S1 · **Область:** backend · **Оценка:** S · **Зависит от:** —
- Настроить конфигурацию доступа к Trello API: получить API key, token и id доски, чтобы бот мог запрашивать карточки с этой доски.
- DoD:
  - [ ] Конфигурация с ключами API Trello сохранена в переменных окружения
  - [ ] Тестовый запрос к Trello API возвращает список карточек доски
- Проверка: curl запрос к https://api.trello.com/1/boards/{id}/cards с ключами возвращает 200 и JSON со списком карточек

### I-002 · Реализовать выборку карточек с дедлайном сегодня или просроченных

## Отложено

| Скоп | Название | Причина |
|---|---|---|
| S7 | Напоминание за N дней до дедлайна | Это расширение уведомлений сверх сквозного сценария «сегодня/просрочено» из MVP; полезно для профилактики срывов сроков, но не критично для базовой ценности продукта — избавления от ручной ежедневной проверки доски. |
| S8 | Ручной запрос сводки по команде в чате | Вспомогательный интерфейс сверх автоматической ежедневной сводки; требует отдельной обработки входящих команд в чате, что расширяет скоуп интеграции с мессенджером за пределы одностороннего вывода сообщений. |
| S9 | Хранение истории отправленных напоминаний | Продукт спроектирован как получающий актуальные данные из Trello при каждом запуске без сохранения состояния; хранение истории добавляет отдельное хранилище и его синхронизацию, что не требуется для решения главной проблемы ежедневной проверки дедлайнов. |
| S10 | Личные сообщения участникам по дедлайнам | MVP ограничен уведомлением в единственный общий командный чат; личные сообщения — отдельный канал коммуникации, требующий дополнительной настройки прав доступа к личным сообщениям каждого участника и сопоставления Trello-аккаунтов с аккаунтами в мессенджере. |

## Открытые вопросы

- Какой мессенджер использует команда для чата (Slack/Telegram/Discord) — от этого зависит реализация I-005 и I-006
- Правило отображения карточек без назначенного ответственного (пропускать/помечать/писать «без ответственного») — от этого зависит реализация I-010
- Нужны ли напоминания по выходным дням или сводка только по будням — от этого зависит реализация I-011
- Ресёрч не проведён: главная проблема и конкурентный ландшафт не подтверждены (outputs/research.md)
- Метрики успеха MVP не заданы бизнесом
- Профессиональный контекст команды (размер, роль, опыт работы с Trello) не определён
