## Фаза 1 — Сквозной сценарий

Цель: Бот раз в день в 9:00 получает из Trello карточки с дедлайном сегодня или просроченные, указывает ответственного по каждой и публикует сводку в единственный командный чат.

### I-001 · Настроить подключение к Trello API
- **Скоп:** S1 · **Область:** infra · **Оценка:** S · **Зависит от:** —
- Нужно получить API key и token Trello с доступом к целевой доске и сохранить их в конфигурации сервиса. Это базовая предпосылка для любого обращения к Trello.
- DoD:
  - [ ] Ключ и токен сохранены в конфигурации/секретах сервиса
  - [ ] Тестовый запрос к Trello API с этими данными возвращает успешный ответ
- Проверка: Тестовый запрос к Trello API с полученным токеном возвращает 200 и список досок

### I-002 · Получить список карточек с доски через Trello API
- **Скоп:** S1 · **Область:** backend · **Оценка:** M · **Зависит от:** I-001
- Реализовать запрос, который забирает все карточки указанной доски вместе с полями due date и участниками. Это исходные данные для дальнейшей фильтрации и сборки сводки.
- DoD:
  - [ ] Функция/эндпоинт возвращает список карточек доски в структурированном виде
  - [ ] В каждой карточке присутствуют поля due date и участники
- Проверка: Скрипт получает JSON со всеми карточками указанной доски, включая due и members

### I-003 · Отфильтровать карточки по дедлайну (сегодня или просрочено)
- **Скоп:** S1 · **Область:** backend · **Оценка:** M · **Зависит от:** I-002
- Из полного списка карточек нужно выбрать только те, у которых due date меньше или равен текущей дате. Это ядро логики, определяющее содержимое ежедневной сводки.
- DoD:
  - [ ] Функция фильтрации принимает список карточек и текущую дату, возвращает только карточки с due ≤ сегодня
  - [ ] На наборе карточек с разными датами (будущее/сегодня/просрочено/без даты) фильтр отрабатывает корректно
- Проверка: На тестовом наборе карточек с разными due date фильтр возвращает только просроченные и сегодняшние

### I-004 · Получить участника Trello, назначенного на карточку
- **Скоп:** S3 · **Область:** backend · **Оценка:** S · **Зависит от:** I-002
- Для карточки нужно определить имя или username назначенного участника из данных Trello API. Это нужно, чтобы в сводке напротив каждой карточки был виден ответственный.
- DoD:
  - [ ] Функция по карточке возвращает имя/username назначенного участника
  - [ ] Для карточки без назначенного участника функция возвращает явное пустое значение, а не ошибку
- Проверка: Для карточки с назначенным участником запрос возвращает его имя/username

### I-005 · Добавить ответственного в данные карточки для сообщения
- **Скоп:** S3 · **Область:** backend · **Оценка:** S · **Зависит от:** I-003, I-004
- Объединить отфильтрованные карточки с данными об ответственных в единую структуру, готовую для сборки текста сообщения. Это связующее звено между выборкой карточек и формированием сводки.
- DoD:
  - [ ] Итоговая структура содержит для каждой отфильтрованной карточки поле assignee
  - [ ] Структура покрывает все карточки из фильтра S1, ни одна не теряется
- Проверка: В итоговой структуре данных каждая карточка содержит поле assignee с именем

### I-006 · Настроить бота в выбранном мессенджере
- **Скоп:** S4 · **Область:** infra · **Оценка:** S · **Зависит от:** —
- Создать приложение/бота в мессенджере командного чата [уточнить: Slack/Telegram/Discord], получить токен доступа и права на публикацию сообщений в целевой чат. Это предпосылка для любой автоматической отправки.
- DoD:
  - [ ] Токен бота с правом публикации в целевой чат сохранён в конфигурации
  - [ ] Ручная отправка тестового сообщения через API мессенджера доходит до чата
- Проверка: Тестовое сообщение от бота успешно публикуется в целевой чат вручную

### I-007 · Реализовать отправку сообщения в чат через API мессенджера
- **Скоп:** S4 · **Область:** backend · **Оценка:** M · **Зависит от:** I-006
- Написать функцию, которая принимает готовый текст и публикует его в единственный командный чат через API выбранного мессенджера. Это финальный шаг доставки сводки пользователю.
- DoD:
  - [ ] Функция принимает произвольный текст и публикует его в целевой чат
  - [ ] Ошибка отправки (например, недоступность API) логируется, а не падает молча
- Проверка: Вызов функции отправки с тестовым текстом публикует сообщение в чат

### I-008 · Сформировать текст сводки с карточками и ответственными
- **Скоп:** S2 · **Область:** backend · **Оценка:** M · **Зависит от:** I-005
- На основе структуры карточек с ответственными собрать читаемый текст сообщения: список карточек с указанием исполнителя по каждой. Это то, что реально увидит команда в чате.
- DoD:
  - [ ] Функция принимает список карточек с ответственными и возвращает готовый текст сообщения
  - [ ] На фиксированном тестовом наборе карточек текст содержит все карточки и всех ответственных
- Проверка: На фиксированном наборе карточек функция формирования текста возвращает ожидаемую строку со списком и ответственными

### I-009 · Настроить ежедневный автоматический запуск сводки в 9:00
- **Скоп:** S2 · **Область:** infra · **Оценка:** M · **Зависит от:** I-003, I-007, I-008
- Настроить планировщик (cron или аналог), который ежедневно в 9:00 запускает полный цикл: выборка карточек, фильтрация, формирование текста и отправка в чат. Это то, что делает продукт автоматическим, а не ручным скриптом.
- DoD:
  - [ ] Планировщик запускает полный цикл ежедневно в 9:00 без ручного вмешательства
  - [ ] В логах видно успешное выполнение цикла минимум за один тестовый день
- Проверка: Планировщик в 9:00 по расписанию запускает полный цикл выборка → сборка → отправка, проверено логами за сутки

## Фаза 2 — Улучшения выборки и расписания

Цель: Сводка корректно обрабатывает карточки без ответственного и поддерживает настраиваемое расписание отправки (будни/все дни).

### I-010 · Обработать карточки без назначенного ответственного
- **Скоп:** S5 · **Область:** backend · **Оценка:** S · **Зависит от:** I-003
- Точное правило отображения карточек без ответственного не зафиксировано в PRD [уточнить: пропускать / помечать отдельно / писать «без ответственного»]. Реализовать нужно один согласованный вариант так, чтобы такие карточки не терялись из сводки.
- DoD:
  - [ ] Карточки без ответственного не исчезают из итогового сообщения
  - [ ] Для них применяется одно и то же явное правило отображения во всех случаях
- Проверка: Карточка без ответственного в тестовом наборе отображается в сообщении согласно выбранному правилу, не исчезает из списка

### I-011 · Добавить конфигурацию расписания отправки (будни/все дни)
- **Скоп:** S6 · **Область:** infra · **Оценка:** S · **Зависит от:** I-009
- Дать возможность настраивать, отправляется ли сводка каждый день или только по будням, через конфигурацию, без изменения кода. Это закрывает открытый вопрос о том, нужны ли напоминания в выходные [уточнить].
- DoD:
  - [ ] Параметр расписания задаётся в конфигурации (будни / все дни)
  - [ ] При включённом режиме «только будни» сообщение не отправляется в выходные
- Проверка: При включённой настройке «только будни» сообщение не отправляется в субботу/воскресенье

## Отложено

| Скоп | Название | Причина |
|---|---|---|
| S7 | Напоминание за N дней до дедлайна | Не входит в сквозной сценарий MVP: требует отдельной секции сообщения и конфигурируемого N, что усложняет первую версию без подтверждённой необходимости. |
| S8 | Ручной запрос сводки по команде в чате | Требует обработки входящих команд от пользователей в чате — отдельный канал взаимодействия, не нужный для автоматической ежедневной доставки в MVP. |
| S9 | Хранение истории отправленных напоминаний | PRD явно исключает эту функцию из MVP: состояние получается заново из Trello при каждом запуске, без сохранения истории отправок. |
| S10 | Личные сообщения участникам по дедлайнам | PRD ограничивает MVP отправкой только в общий командный чат, личные сообщения участникам не предусмотрены. |

- Как именно обрабатывать карточки без ответственного (пропускать/помечать отдельно/писать «без ответственного») — блокирует финальную реализацию I-010.
- Нужны ли напоминания в выходные дни — определяет поведение по умолчанию для I-011.
