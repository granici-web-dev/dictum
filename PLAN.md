## Фаза 2 — Демо-путь к 18.09 (ITCS)  ← ТЕКУЩАЯ

**Что показываем на стенде.** Голосовое в Telegram → карточки в Trello. `auto_approve`, один
пользователь, состояние в памяти процесса, статус-сообщение после каждой стадии, ссылка на доску в
конце. Текст — тот же путь, запасной вход, если голосовое не пройдёт при людях.

**Чего на стенде нет.** Файлов с диска и consent, ворот, диалога брифа, Postgres, ресёрча (идёт в
`skip`). Всё это в фазе 3 и не начинается раньше, чем демо отработает.

Задачи идут строго в этом порядке: каждая следующая опирается на предыдущую.

- [x] P2-00 Хребет пайплайна: делать **до** бота, потому что оба пункта дублируются в воркере, как только он появится (`docs/architecture-review.md`)
  - [x] Список стадий данными (`SPEC §7.2`): имя, исполнитель `llm`/`code`, входы, выходы, параметры. `cli` идёт по списку от стадии в `--from`; лесенка `if from_here <= N` уходит, `STAGE_ORDER` и `STAGES` схлопываются в одну запись
  - [x] `research` — запись списка с исполнителем `code`, а не заглушка, записанная в обход списка веткой в `cli`
  - [x] `run_id` от `ingest` (`SPEC §3.1`, `§5`): выдаётся при записи `transcript.md`, доезжает до `issues.json`, `publish` его только читает и падает, если поля нет. Формат маркера не меняется, доску не чистим
  - [x] Ожидание для P2-01: `ingest` и `publish` входят записями в тот же список, а не заводят у бота свой порядок. Пайплайн бота — тот же список от `ingest` до `publish`, отличается только начало и конец обхода
- [x] P2-01 Бот: режется надвое, потому что обход тестируется без Telegram и без сети, а бот — нет
  - [x] Общий обход: `ingest` и `publish` — записи того же списка стадий, `walk` в `app/run.py`, корень артефактов у прогона свой (`runs/<run_id>/` у бота, текущий каталог у CLI). Дорога у бота и у `make run-text` одна, копии порядка больше нет
  - [x] Бот polling: `/start`, текст → весь пайплайн → publish. Статус-сообщение после каждой стадии, ссылка на доску в конце. Состояние прогона живёт в памяти процесса: одного пользователя и одного прогона за раз для стенда достаточно, а Postgres — это P2-02 после ITCS
    - [x] **Первым делом — белый список `chat_id` в `.env`.** Без него бот тратит деньги по сообщению от любого, кто нашёл его по имени, а на конференции это вопрос времени. Условие первого запуска, не отделочная задача
    - [x] Пайплайн синхронный, бот асинхронный (`CONVENTIONS`): обход уходит в `asyncio.to_thread`, иначе бот молчит три минуты
    - [x] Второй прогон при живом первом — отказ с объяснением, а не очередь
- [x] P2-05 `auto_approve` режимом прогона: ворот ещё нет, но флаг и его семантика в `SPEC §3.2` уже описаны, и бот идёт именно по этой ветке, а не в обход неё. Когда ворота появятся, включать будет нечего
  - [x] Ворота — поле записи стадии (`gate_after`), а не ветка у вызывающего: колонка «Ворота после» из `SPEC §3` стала данными, и копия порядка не заводится у бота с воркером
  - [x] Обход отдаёт остановку с родом: выбор идеи из нескольких `auto_approve` не снимает — подтверждать там нечего, а выбрать за человека значит выдумать данные. Ограничение демо записано в `SPEC §3.2`
  - [x] `make run-text TEXT="…" ARGS=--gates`: ветку с воротами можно пройти руками до P2-03, а не только в тестах. Рецепт `run-text` получил `ARGS`, иначе флаг было не передать
  - [x] Живая проверка на `fixtures/idea_text.md`: обход встал после brief, код `2`, сообщение назвало артефакт и `--from research`. Прогон нашёл, что логгер CLI звался `__name__`, а под `python -m app.cli` это `__main__` мимо дерева `app`: свои сообщения CLI глотал, и «Идей несколько» человек тоже никогда не видел. Починено там же
- [ ] P3-01 Голосовое `.oga` → ffmpeg → Whisper → `transcript.md` → дальше тот же путь, что и у текста. Главный вход демо
  - [x] Расшифровка — стадия `ingest`, а не обработчик бота: `app/transcribe.py` держит границу (ffmpeg и Whisper), `Run.audio` включает ветку, дорога после `transcript.md` у голосового и текста одна
  - [x] Язык прогона называет Whisper: `Run.lang` до расшифровки хранит `DEFAULT_LANG`, после — распознанный, и `brief` получает уже его. Имя языка от Whisper (`russian`) переводится в код таблицей; незнакомое идёт как есть, потому что соврать про язык хуже

  - [ ] Живой прогон: голосовое в бот → доска. Тратит два ключа сразу, поэтому идёт отдельным решением, а не следом за зелёными тестами
- [ ] P2-06 Репетиция: пять живых прогонов подряд на `Dictum Demo` с очисткой доски между ними, замер времени и цены каждого, отчёт в `docs/`. Последняя задача перед стендом: она отвечает на вопрос «сколько человек ждёт у стенда и во сколько это обходится», а не «работает ли»
  - [ ] Один из пяти прогонов — с телефонного хотспота при закрытой крышке (сон отключён): на стенде будет ровно это, а не домашний wi-fi. Сорвётся — P4-03 (деплой на Hetzner, webhook вместо polling) едет вперёд, в фазу 2, потому что ноутбук на столе перестаёт быть площадкой
